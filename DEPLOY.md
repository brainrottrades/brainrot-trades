# Deploying Brainrot Trades live (Render)

## Permanent hosting — Starter + persistent disk (Nov 23, 2026)

Patrick chose to make the site permanent: the database no longer wipes on
deploy. Setup (Render dashboard, service `brainrot-trades`):

- **Plan: Starter ($7/month)** — paid instances never sleep, and only paid
  instances can attach a disk. The card already on file is charged.
- **Persistent disk: 50 GB ($12.50/month), mount path `/data`** — the
  database and uploaded pictures live on it and survive every deploy.
  (Patrick picked 50 GB on Nov 23, 2026; disks are $0.25/GB/month.)
- **Env var `DATA_DIR=/data`** — server.js stores `app.db` and uploads
  under `DATA_DIR` when it is set; without it, data lives in `./data`
  (local dev, and the old free-tier behaviour).
- **One last wipe:** the deploy that turns the disk on still starts from an
  empty database (the old ephemeral one is gone). Everyone signs in once
  with Google after that deploy, and from then on nothing wipes.
- **Proof it sticks:** after the disk deploy, create a test account on the
  live site, then run a second deploy of the same commit — the account must
  still log in afterwards. (Starter also has shell access, so the disk can
  be checked directly: the file is `/data/app.db`.)
- Total: about **$19.50/month** (Starter $7 + 50 GB disk $12.50). Uploaded sale pictures now survive deploys
  too (they are stored under `DATA_DIR/uploads` and served at `/uploads`).

The code is finished, verified locally, and committed as a git repo in this
folder (`git log` shows the v1 commit; 100 files, including all 86 brainrot
pictures). This document is the exact checklist for putting it live.

## What a browser task still has to do (Muse cannot do these from the shell)

Render has no signup API and no CLI login without a dashboard API key, so
creating the account and the service needs a logged-in browser session.
No payment details are needed anywhere below — free tier only.

### 1. Get the code onto GitHub

- Create a GitHub account for Patrick if he does not have one
  (email `pgevil22@gmail.com`; if GitHub asks for an email verification
  code, stop and ask Patrick for it — do not guess).
- Create a new **public** repo, e.g. `brainrot-trades-website`.
- Push this folder to it. From the VM shell, once GitHub auth exists:
  ```bash
  cd ~/workspace/brainrot-website
  git remote add origin https://github.com/<user>/brainrot-trades-website.git
  git push -u origin main
  ```
  (If the default branch is `master` locally, rename it first:
  `git branch -M main`.)

### 2. Create the Render account

- Go to https://render.com — sign up with email `pgevil22@gmail.com`
  (or "Sign up with GitHub" using the account from step 1).
- Free plan. **Do not enter any payment details.** Render's free tier
  needs no card.
- If Render asks for an email verification code, stop and report it:
  the code goes to Patrick's email and someone has to fetch it from him.

### 3. Create the web service

- Render dashboard → **New → Web Service** → connect the GitHub repo
  from step 1.
- Render detects `render.yaml` in the repo: service name
  `brainrot-trades`, runtime Node, plan **Free**, build `npm install`,
  start `node server.js`.
- Create the service. First deploy takes a few minutes. The live URL
  will be like `https://brainrot-trades.onrender.com`.

### 4. Set the environment variables (Render → service → Environment)

| Variable | Value | Required? |
|---|---|---|
| `DATA_DIR` | `/data` (the persistent disk mount path) | Required on Render since Nov 23, 2026 — without it the database goes back to `./data` and wipes on deploy. |
| `SESSION_SECRET` | auto-generated by `render.yaml` | Yes (auto) |
| `PAYPAL_CLIENT_SECRET` | From the PayPal dashboard: Developer → My Apps & Credentials → Live → "Brainrot Trades" → Secret | Recommended — without it, subscriptions are recorded from checkout only and the admin panel says so. **Never paste the Secret in chat.** Patrick has to copy it from PayPal himself. |
| `SENDGRID_API_KEY` / `SENDGRID_FROM` | **Recommended on Render.** Free SendGrid account (100 emails/day): verify `pgevil22@gmail.com` as a Single Sender, create an API key with Mail Send permission, set it here (`SENDGRID_FROM` defaults to `pgevil22@gmail.com`). Sends over HTTPS, so it works where SMTP is blocked. | Only used by the old verification-code flow, which the site no longer offers (Google sign-in + owner approval replaced it). Not needed for normal operation. |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | From Google Cloud Console: project "Brainrot Trades" → APIs & Services → Credentials → OAuth client "Brainrot Trades website". Redirect URI must be `https://brainrot-trades.onrender.com/api/auth/google/callback`. **Never paste the Secret in chat.** | Required for Google sign-in. Without them the Google button is hidden. The OAuth consent screen must also be **Published** (needs the site's privacy policy URL, `/privacy`) or only the listed test users can sign in. |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_SECURE` / `SMTP_USER` / `SMTP_PASS` / `SMTP_FROM` | Gmail SMTP (`smtp.gmail.com`, 587, false) + a Gmail **app password** | **Does NOT work on Render free tier** — Render blocks outbound SMTP (ports 587 and 465 both time out; confirmed Nov 22, 2026). Kept only as a fallback for hosts that allow SMTP. |

After setting env vars, Render redeploys automatically.

## Pushing code updates (learned Nov 22, 2026)

- Code is pushed to the GitHub repo (`brainrottrades/brainrot-trades`,
  branch `master`) via the GitHub web UI, one commit per file, full
  content replacement — the sandbox shell has no git auth.
- **Auto-deploy does NOT fire on commit** even though the service shows
  Auto-Deploy "On Commit": after pushing, check the Render deploys page
  and if no new deploy started within a few minutes, use **Manual
  Deploy → Deploy latest commit**. (Confirmed Nov 22, 2026: the 5a8844b
  push sat for 9 minutes with no deploy until a manual deploy ran it.)
- Deploys no longer wipe the database (persistent disk since Nov 23, 2026 —
  see "Permanent hosting" above). Before the disk, every deploy wiped it.
- After a deploy, verify with a cache-busted fetch: a plain fetch of
  `/app.js` right after a deploy can return the previous version.

## Free-tier caveats (tell Patrick plainly)

- The service **used to sleep after 15 minutes with no traffic** on the
  free tier; on Starter (since Nov 23, 2026) it stays up, so the first
  visit loads instantly.
- The **filesystem used to be ephemeral**: on the free tier the SQLite
  database reset on every redeploy. Fixed Nov 23, 2026 with the persistent
  disk (see "Permanent hosting" above) — accounts, chats, trades, sales,
  messages, friends and uploaded pictures now survive deploys.
- Email: use SendGrid (step 4) — Render blocks outbound SMTP, so Gmail
  SMTP cannot send from this service. Render does not send email for you.

## If Render does not work

Fallback free hosts for a Node + SQLite app: Railway (free trial credit,
no card to sign up) or Fly.io — **but Fly.io requires a credit card on
file even for the free tier, so do not use it** (no payment details).
Replit free tier is another fallback. All of them still need a browser
signup the same way.
