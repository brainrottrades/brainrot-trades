# Deploying Brainrot Trades live (Render free tier)

The code is finished, verified locally, and committed as a git repo in this
folder (`git log` shows the v1 commit; 100 files, including all 86 brainrot
pictures). This document is the exact checklist for putting it live.

## What a browser task still has to do (Muse cannot do these from the shell)

Render has no signup API and no CLI login without a dashboard API key, so
creating the account and the service needs a logged-in browser session.
No payment details are needed anywhere below — free tier only.

### 1. Get the code onto GitHub

- Create a GitHub account for Patrick if he does not have one
  (email `pgevil22@gmail.com`; if GitHub asks for an email verification
  code, stop and ask Patrick for it — do not guess).
- Create a new **public** repo, e.g. `brainrot-trades-website`.
- Push this folder to it. From the VM shell, once GitHub auth exists:
  ```bash
  cd ~/workspace/brainrot-website
  git remote add origin https://github.com/<user>/brainrot-trades-website.git
  git push -u origin main
  ```
  (If the default branch is `master` locally, rename it first:
  `git branch -M main`.)

### 2. Create the Render account

- Go to https://render.com — sign up with email `pgevil22@gmail.com`
  (or "Sign up with GitHub" using the account from step 1).
- Free plan. **Do not enter any payment details.** Render's free tier
  needs no card.
- If Render asks for an email verification code, stop and report it:
  the code goes to Patrick's email and someone has to fetch it from him.

### 3. Create the web service

- Render dashboard → **New → Web Service** → connect the GitHub repo
  from step 1.
- Render detects `render.yaml` in the repo: service name
  `brainrot-trades`, runtime Node, plan **Free**, build `npm install`,
  start `node server.js`.
- Create the service. First deploy takes a few minutes. The live URL
  will be like `https://brainrot-trades.onrender.com`.

### 4. Set the environment variables (Render → service → Environment)

| Variable | Value | Required? |
|---|---|---|
| `SESSION_SECRET` | auto-generated by `render.yaml` | Yes (auto) |
| `PAYPAL_CLIENT_SECRET` | From the PayPal dashboard: Developer → My Apps & Credentials → Live → "Brainrot Trades" → Secret | Recommended — without it, subscriptions are recorded from checkout only and the admin panel says so. **Never paste the Secret in chat.** Patrick has to copy it from PayPal himself. |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_SECURE` / `SMTP_USER` / `SMTP_PASS` / `SMTP_FROM` | Gmail SMTP (`smtp.gmail.com`, 587, false) + a Gmail **app password**, or SendGrid/Mailgun credentials | Needed for verification-code emails. Without them the site runs in dev mode and prints codes to the server log — members cannot sign up. |

After setting env vars, Render redeploys automatically.

### 5. Verify the live URL

- Open the URL: the landing page loads (headline, 8 features, 6 sample
  brainrots, $3/month, Sign up / Log in).
- Sign up with a test email, verify with the code from the inbox,
  subscribe flow shows the PayPal button, price list loads after
  subscribing (or after the owner grants access).
- Log in as the owner (`pgevil22@gmail.com`) to confirm the Admin panel
  appears.

## Free-tier caveats (tell Patrick plainly)

- The service **sleeps after 15 minutes with no traffic**; the first
  visit after a sleep takes ~30–60 seconds to wake up.
- The **filesystem is ephemeral**: the SQLite database resets on every
  redeploy, so members, chats, trades, sales, messages and friends made
  on the free tier can be lost when the service redeploys. Fine for
  launching and testing; before real paying members join, move to paid
  hosting (see README.md — DigitalOcean $4/month VPS recommended).
- Email still needs real SMTP credentials (step 4) — Render does not
  send email for you.

## If Render does not work

Fallback free hosts for a Node + SQLite app: Railway (free trial credit,
no card to sign up) or Fly.io — **but Fly.io requires a credit card on
file even for the free tier, so do not use it** (no payment details).
Replit free tier is another fallback. All of them still need a browser
signup the same way.
